 Semantius with MICROSOFT ENTRA ID: PostgreSQL with the pg_semantius extension,
 a PostgREST HTTP API, its OpenAPI docs and the web app, behind one Caddy front
 door. No identity provider is included — your Entra tenant signs the tokens,
 and this stack only verifies them.

 IT WILL NOT START UNTIL IT IS CONFIGURED. Four steps, in README.md:

   1. ./setup-env.sh        create .env (Windows: setup-env.cmd)
   2. ./setup-entra.ps1     register the three applications in your tenant
                            and write their ids into .env — or do it in the
                            Entra admin center and fill .env yourself
   3. assign people to the `authenticated` app role, in Entra
   4. ./up.sh               start (Windows: up.cmd)

 Everything Entra needs that is the same for every tenant is already set below:
 the `.roles[0]` claim key, the empty JWKS_URL that derives signing keys from
 the discovery document, and the account menu. What belongs in .env is only
 yours — the tenant, the app ids, the audience.

 NOT INCLUDED, because the identity provider is not: the /idp and /gateway
 routes, API keys, and the API docs' one-click "Test Request" (paste a bearer
 token into the docs' Authentication box instead). Signing keys are refreshed
 manually — README.md says when and how.
