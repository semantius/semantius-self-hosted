 The Semantius stack against MICROSOFT ENTRA ID: PostgreSQL with the
 pg_semantius extension, a PostgREST HTTP API, its OpenAPI docs and the admin
 SPA, behind one Caddy front door. No identity provider is included — Entra
 signs the tokens, and this stack only verifies them.

 Everything Entra needs that is the same for every tenant is already set here:
 the `.roles[0]` claim key (Entra cannot emit a claim called `role`), the empty
 JWKS_URL that derives the keys from discovery, and an account menu pointing at
 Microsoft's My Account. What is left for .env is only YOURS: the tenant, the
 app ids, the audience.

 IT WILL NOT START UNTIL IT IS CONFIGURED, by design. Copy .env.example to .env
 and fill the first block: the issuer's discovery URL, the client id for the
 SPA, the audience and scope its tokens are minted for, and the audience this
 stack requires. Compose refuses to start while any of them is empty.

   ./setup-entra.ps1        creates the three app registrations in your tenant
                            and writes .env (README.md explains every step, and
                            how to do it by hand)
   ./up.sh                  start

 WHAT ENTRA MUST DO: mint an access token carrying an app role named
 `authenticated` and a stable `sub`. Users are created in the database on first
 sign-in from that `sub`. Assigning people to that app role is what grants
 access to this stack at all.

 GONE WITH THE IDENTITY PROVIDER: the /idp and /gateway routes, API keys, and
 the docs' one-click "Test Request" (it used the idp's authenticating proxy;
 paste a bearer token instead). Key rotation is manual here — the repository
 README says when and how.
